# 行程与聊天云端同步

## 使用方式

计划页增加“同步”和“历史行程”。登录后自动同步，编辑先保存本机；前台会话存活期间，本地修改会触发上传，无修改时约每分钟检查其他设备的更新。网络失败可手动重试，重启 App 也会继续处理保存的请求。

每次生成新的攻略会保存为独立行程；更换目的地先创建新草稿，旧行程和对话留在历史列表。空草稿生成攻略时复用其 ID，避免重复创建。历史行程选择后，地图、计划、配置和聊天一起恢复。

尚未下载过的云端历史行程需要联网打开；已下载的行程可以离线切换。此版本历史接口最多返回最近 200 份云端行程，本机已有历史不受此上限影响。

## 冲突处理

- 每份行程使用 UUID `tripId`；服务端保存递增 `version`。
- 一个文档包含 `plan`、`messages`、`options`，聊天提议原文和确认状态也会同步。
- 写入携带 `baseVersion` 和固定 `mutationId`。版本不匹配返回 HTTP 409，不覆盖云端。
- 上传前将请求正文和发送时的本地修订号写入 Room。网络超时或响应丢失时，重试原请求，不重新生成请求 ID。
- ACK 只确认发送时的修订。上传期间继续编辑，较新的内容仍为待上传状态。
- 冲突界面可以选择使用云端，或把本地内容另存为新行程。无论选哪种，都先保存本地副本；原云端内容不会被强制覆盖。
- 服务端保存每个成功版本与请求收据，版本写入、收据和当前指针更新由数据库事务保护。
- 正在生成攻略、等待 Agent 回复或确认提议时，不自动切换云端行程。

## 数据与账号

Android 账号分库继续生效。新增 Room 版本 9 的 `trip_sync_state` 和 `trip_sync_active` 表，8→9 迁移仅新增表。`travel_plan`、`plan_item` 和 `chat_history` 作为当前行程的展示缓存；全部历史按 UUID 保存。

首次启用时，仅将当前账号分库中的行程和聊天纳入同步；不会认领旧的无归属共享库 `citygo_app.db`。旧共享数据仍需确认归属，不能自动上传给当前账号。

后端用户 ID 从 JWT 拦截器注入，不接受客户端指定的所有者。其他账号读取、写入或激活该行程均返回 404。鉴权失败统一返回 HTTP 401 和业务码 401，使客户端能够处理登录过期。

## 后端接口

工程位置：`C:/login/login-demo`。

| 接口 | 用途 |
| --- | --- |
| `GET /api/me/trips` | 当前用户历史行程摘要 |
| `GET /api/me/trips/current` | 当前用户的云端当前行程，无行程时 data 为 null |
| `GET /api/me/trips/{tripId}` | 读取完整行程及聊天 |
| `PUT /api/me/trips/{tripId}` | 版本校验保存，返回新版本；冲突返回 409 及云端快照 |
| `POST /api/me/trips/{tripId}/activate` | 选择云端当前行程，不覆盖内容 |

写入示例：

```json
{
  "baseVersion": 0,
  "mutationId": "7aed9392-2b14-47ad-b3e4-d9d8e9344c53",
  "title": "成都",
  "document": { "plan": null, "messages": [], "options": null },
  "makeCurrent": false
}
```

Android 在内容上传后单独激活当前行程；上传后台历史副本不会顺带切换云端当前指针。

## 启用部署

需要重启使用新代码的后端，并安装新的 Android APK。

后端启动器 `TripSyncSchema` 使用 `src/main/resources/db/trip-sync.sql`，只创建三个新增的 InnoDB 表：`citygo_trip`、`citygo_trip_revision`、`citygo_trip_current`，不修改已有业务表。数据库用户需要建表权限；没有权限时，可先由管理员执行同一脚本。

这次工作不终止或重启用户正在运行的后端，也不自动安装 APK。已有旧服务进程在重启前不会提供新接口，手机会显示未同步并保留本地修改。

- 后端服务、JWT/HTTP 接口与已有业务共 18 项测试通过。
- 真实 MySQL 验证仅创建连接级临时表，覆盖事务写入、所有者隔离、冲突回滚与请求重放；未写入现有业务表。

- 空行程 `plan:null` 和原始请求逐字节重试协议已补充回归；本机 SQLite 检查确认迁移新增表与 Room 生成的 schema 一致。
- 设备测试包含 8→9 迁移、上传期间编辑、响应丢失后重建同步器、冲突另存副本。当前未连接设备，因此这些设备测试尚未运行。

## 当前范围

本轮同步行程、旅行配置、Agent 对话及提议状态；宠物、日记、收藏等数据仍使用此前的本地账号隔离方案。
没有增加后台 WorkManager：App 进程被系统结束后不保证立即上传，未完成修改会在下次打开并登录时继续同步。已同步的数据可换设备恢复；尚未同步的离线数据在卸载后无法恢复。
